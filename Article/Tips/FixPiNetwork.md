# 记一次排查 Pi Agent 不能用xxx公益站的问题 {#debug-pi-agent}

## 前言 {#introduction}

事情是这样的,大家看我之前的帖子,就知道我最近在折腾 `Pi` 和 `Reasonix` 这两个Agent.

我在 Pi 里接入了某公益站模型后,对话后直接返回了403, 当时还和站长私聊,研究了一下,没整明白.

![插图-私聊记录](/imgs/1786253216001.avif)

后来我开始用 Reasonix(桌面端) 的时候, 对接了上次的公益站, 发现可以正常对话了, 启动Pi 测试发现还是403.

![插图-agent聊天对比](/imgs/1786254644683.avif)

嘶... 我不服, 我要盘它!

## 环境准备 {#environment-setup}

我是个前端开发, 之前玩过爬虫, 我首先想到的就是UA验证

但是看不到 Pi 和 Reasonix 的请求,他们并不是浏览器, 我想到了用抓包软件

传统的抓包软件有Fiddler、Charles等, 很早以前都用过, 这次我用了个新的软件 reqable

英文名字有点陌生, 但中文名字好记, 叫小黄鸟

![插图-谷歌搜索](/imgs/1786253216002.avif)

下载->安装->安装证书(抓包软件都要装,不然没办法抓https包)

现在9成9都是 https 流量, 如果不装证书, 就像你打电话我不接,你打它有啥用呢?

![插图-疯狂的石头下水道打电话](/imgs/1786253578154.avif)

言归正传, 因为懂得都懂的原因, 我电脑上已经有个代理软件了, 但是要运行抓包软件, 这俩要争抢代理权,

那怎么办呢?

好的一点是,这小黄鸟支持设置二级代理, 让流量先经过小黄鸟, 然后自动转发给代理软件, 完美!

![插图-小黄鸟配置二级代理](/imgs/1786255790475.avif)

Fiddler、Charles支不支持二级代理不清楚, 现在支不支持中文我都不清楚了, 因为早年我用的时候俩都是纯英文的

好了,环境都准备完成了准备抓包!

## 抓包分析 {#packet-analysis}

启动小黄鸟监控, 打开pi, 发出请求, 老样子还是 403 , 但这次抓到了请求报文,看看UA

![插图-小黄鸟捕获的 pi 报文](/imgs/1786256626721.avif)

继续打开 reasonix , 使用同一个供应商的同一个模型, 发出请求, 正常回复, 抓取报文,查看UA

![插图-小黄鸟捕获的 reasonix 的报文](/imgs/1786256841512.avif)

题外话, 如果看不懂抓包软件,可以配置抓包软件的MCP,直接交给AI分析

![插图-配置MCP的插图-1](/imgs/1786253894469.avif)
![插图-配置MCP的插图-2](/imgs/1786253926091.avif)

让AI启用MCP开始分析

![插图-reasonix 使用MCP的过程](/imgs/1786254094593.avif)

两个 Agent 的UA 果然不一样,看看能不能修改 pi 的报文,去官网看看

https://pi.dev/docs/latest/models#custom-headers

![插图-Pi官网 headers 配置图](/imgs/1786253216003.avif)

果然是支持的,Pi 牛逼!

现在通过配置,把自定义UA补上,

![插图-补充UA,抄 reasonix 的UA](/imgs/1786257664313.avif)

重启pi或者`/reload`,重新提问测试
